ESAS Configuration & Pipeline (``esas.toml``)
=============================================

All ``xmm-esas`` reduction stages are driven by a single commented ``esas.toml``
configuration file generated by ``xmm-esas init``. Each stage writes a
``manifest.json`` contract so downstream steps automatically locate cleaned
events, swiss-cheese masks, flux images, extracted spectra, and ``protonscale``
values—and so completed stages are safely skipped on subsequent runs unless
``--force`` is passed.

Pipeline Overview
-----------------

The ESAS workflow separates one-time observation initialization from the
config-driven analysis pipeline:

.. code-block:: text

   Raw ODF ──▶ xmm-esas init ──▶ esas.toml + ccf.cif + *SUM.SAS + *_evt.fits
                                        │
                                        ▼  (xmm-esas run  — all or selected stages)
                        ┌───────────────┴───────────────┐
                        ▼                               │
                     [flare]                            │
             soft_proton_flare/manifest.json            │
                        │                               │
                ┌───────┴────────┐                      │
                ▼                ▼                      │
            [cheese]       [quick-image]                │
       cheese/manifest.json  quick_image/manifest.json  │
                │                │                      │
                │         (inspect in xmm-img           │
                │          & draw DS9 .reg files)       │
                └───────┬────────┘                      │
                        ▼                               │
                   [spectrum]  ◀────────────────────────┘
             spectrum/manifest.json  ──▶ xmm_tools.sherpa

.. list-table:: ESAS Stages & Manifest Contracts
   :header-rows: 1
   :widths: 15 25 30 30

   * - Stage
     - SAS Tasks
     - Output Directory & Manifest
     - Key Products
   * - ``init`` *(one-time setup)*
     - ``cifbuild``, ``odfingest``, ``emchain``, ``epchain`` (normal + OOT)
     - ``<workdir>/esas.toml``
     - ``ccf.cif``, ``*SUM.SAS``, standardized ``mos1_evt.fits``, ``mos2_evt.fits``, ``pn_evt.fits``, ``pn_oot_evt.fits``
   * - ``flare``
     - ``espfilt``, ``evselect`` (ESAS FLAG filter)
     - ``soft_proton_flare/manifest.json``
     - ``*-allevc.fits``, ``*-allevcoot.fits``, ``*-hist.qdp``, ``*-gti.fits``
   * - ``cheese``
     - ``cheese`` (``edetect_chain`` + mask generation)
     - ``cheese/manifest.json``
     - ``emllist.fits``, ``*-cheeset.fits``, ``*-bkgregtdet.fits``, ``*-bkgregtsky.fits``
   * - ``quick-image``
     - ``atthkgen``, ``evqpb``, ``eimageget``, ``eimagecombine``
     - ``quick_image/manifest.json``
     - QPB-subtracted, vignetting-corrected ``<band>_<emin>_<emax>_flux.fits``
   * - ``spectrum``
     - ``evselect``, ``ecoordconv``, ``mosspectra``/``pnspectra``, ``mosback``/``pnback``, ``protonscale``
     - ``spectrum/manifest.json``
     - Per-region ``*-fovt.pi``, ``*-fovtootsub.pi``, ``*-bkg.pi``, ``.rmf``, ``.arf``, QDP plots, ``proton_scale``

1. One-Time Observation Initialization (``xmm-esas init``)
----------------------------------------------------------

Run ``xmm-esas init`` once per observation to build the calibration index,
ingest the ODF, run ``emchain``/``epchain`` (normal + Out-of-Time), standardize
the event filenames, and generate a commented ``esas.toml``:

.. code-block:: bash

   xmm-esas init --odf-dir /path/to/ODF --workdir ./esas_work --ccfpath /ccf/valid

   # Or execute SAS commands inside a running Docker container:
   xmm-esas init --odf-dir /path/to/ODF --workdir ./esas_work --docker xmm-sas-workdir

Useful flags for ``init``:

- ``--copy-events``: copy standardized ``*_evt.fits`` instead of symlinking from ``_chain_work/``.
- ``--dry-run``: validate arguments without running SAS or writing files.
- ``--force``: re-run ``cifbuild``/``odfingest``/chains even if outputs already exist.

After ``init`` finishes, review and edit ``esas.toml`` as needed (for example,
disabling a missing instrument or tuning energy bands).

2. Running the Pipeline (Automatic, Selective, or Step-by-Step)
---------------------------------------------------------------

Once ``esas.toml`` exists, you can run all config-driven stages automatically,
run a specific subset/range of stages, or invoke any individual stage directly.

Run All Stages Automatically
~~~~~~~~~~~~~~~~~~~~~~~~~~~~

.. code-block:: bash

   # Run flare -> cheese -> quick-image -> spectrum in dependency order
   xmm-esas run --config esas.toml

   # Inside a Docker container, or validate first with --dry-run
   xmm-esas run --config esas.toml --docker xmm-sas-workdir
   xmm-esas run --config esas.toml --dry-run

.. note::

   - **Smart caching**: Stages whose ``manifest.json`` and core outputs already
     exist are automatically skipped unless you pass ``--force``.
   - **Pre-region convenience**: If ``[[spectrum.regions]]`` is not configured
     yet in ``esas.toml``, ``xmm-esas run`` cleanly runs ``flare`` ->
     ``cheese`` -> ``quick-image`` and skips ``spectrum`` with a notice. After
     you inspect the flux image in ``xmm-img`` and add ``[[spectrum.regions]]``
     to ``esas.toml``, running ``xmm-esas run`` again skips the already-finished
     stages and executes ``spectrum``.

Run Specific Stages or a Stage Range
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Use ``--stages``, ``--from``/``--to``, or ``--skip`` to run any subset of
``flare``, ``cheese``, ``quick-image``, and ``spectrum``:

.. code-block:: bash

   # Run only flare and cheese (comma-separated or repeatable)
   xmm-esas run --config esas.toml --stages flare,cheese

   # Run a contiguous range of stages
   xmm-esas run --config esas.toml --from cheese --to spectrum

   # Run everything except quick-image
   xmm-esas run --config esas.toml --skip quick-image

   # Re-run cheese and spectrum, restricting spectrum to one region group
   xmm-esas run --config esas.toml --stages cheese,spectrum --only background --force

Accepted stage aliases: ``espfilt`` (``flare``), ``source-detect`` /
``source_detect`` (``cheese``), ``quick_image`` / ``image`` (``quick-image``),
and ``spectra`` (``spectrum``).

Run Individual Stages Step-by-Step
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Every stage also remains available as its own subcommand:

.. code-block:: bash

   xmm-esas flare --config esas.toml
   xmm-esas cheese --config esas.toml
   xmm-esas quick-image --config esas.toml
   xmm-esas spectrum --config esas.toml

   # Spectrum-specific incremental shortcuts:
   xmm-esas spectrum --only background --force
   xmm-esas spectrum --reg regions/new_knot.reg --name knot1 --mode single

3. Complete Annotated ``esas.toml`` Example
-------------------------------------------

Below is a full, self-contained ``esas.toml`` showing **every** supported
section and parameter with its default value, unit, and purpose:

.. code-block:: toml

   # ============================================================================
   # XMM-Newton ESAS Analysis Configuration (full annotated example)
   # ============================================================================

   [env]
   sas_ccf = "ccf.cif"                   # Calibration index file (generated by cifbuild)
   sas_ccfpath = "/ccf/valid"            # Path to XMM-Newton CCF calibration repository
   sas_odf = "1234_0204870101_SCX00000SUM.SAS"  # ODF summary file (*SUM.SAS from odfingest)
   regions_path = ""                     # Optional fallback dir containing 'regions' package
                                         # (e.g. "/tmp/xmm-coordinates-deps" inside offline Docker)

   [paths]
   workdir = "."                         # Root analysis directory (relative to this TOML or absolute)
   flare_dir = "soft_proton_flare"       # Subdirectory for espfilt + ESAS FLAG filtering
   cheese_dir = "cheese"                 # Subdirectory for point-source detection and masks
   spectrum_dir = "spectrum"             # Subdirectory for extracted spectra & particle backgrounds
   image_dir = "images"                  # Subdirectory for multi-band imaging products

   [instruments]
   # Standardized event filenames produced by `xmm-esas init`.
   # Set any instrument to "" to disable it across ALL downstream stages.
   mos1 = "mos1_evt.fits"
   mos2 = "mos2_evt.fits"
   pn = "pn_evt.fits"
   pn_oot = "pn_oot_evt.fits"            # Out-of-Time event list for EPIC-pn

   # ----------------------------------------------------------------------------
   # Stage 1: Soft-Proton Flare Filtering (`xmm-esas flare`)
   # ----------------------------------------------------------------------------
   [espfilt]
   elow = 2500                           # Lower energy bound for flare light curve / histogram (eV)
   ehigh = 8500                          # Upper energy bound for flare light curve / histogram (eV)
   withsmoothing = true                  # Smooth light curves before histogram fitting
   smooth = 51                           # Boxcar smoothing width (seconds)
   rangescale_mos = 6.0                  # Histogram range scale factor for MOS1 / MOS2
   rangescale_pn = 15.0                  # Histogram range scale factor for EPIC-pn
   allowsigma = 3.0                      # Good-time acceptance half-width (in Gaussian sigma)
   method = "histogram"                  # espfilt filtering method: "histogram" or "ratio"
   keepinterfiles = false                # Keep SAS temporary files inside espfilt
   apply_flag_filter = true              # Run ESAS evselect FLAG filter on *-allevc.fits
   mos_flag_expr = "((FLAG & 0x766aa000)==0)"
   pn_flag_expr = "((FLAG & 0x762a097c)==0)"

   # ----------------------------------------------------------------------------
   # Stage 2: Point-Source Detection & Swiss-Cheese Masking (`xmm-esas cheese`)
   # ----------------------------------------------------------------------------
   [source_detect]
   method = "cheese"                     # Point-source detector backend ("cheese")
   elowlist = [350, 2500]                # Lower energy bounds for detection bands (eV)
   ehighlist = [1100, 8000]              # Upper energy bounds for detection bands (eV)
   scale = 0.4                           # PSF-scaled mask radius factor (larger = bigger holes)
   mlmin = 15.0                          # emldetect minimum detection likelihood threshold
   dist = 50.0                           # Minimum separation between detected sources (arcsec)
   ratesoft = 0.2                        # Soft-band flux/rate threshold for masking
   ratehard = 0.2                        # Hard-band flux/rate threshold for masking
   ratetotal = 0.2                       # Total-band flux/rate threshold for masking
   keepinterfiles = false                # Let SAS clean up its own temporary files
   extra_regions = []                    # Optional extra DS9 .reg files to exclude (e.g. ["regions/bright_star.reg"])
   extra_params = {}                     # Extra key=value parameters passed through to `cheese`

   # ----------------------------------------------------------------------------
   # Stage 3: Quick-Look QPB-Subtracted Flux Imaging (`xmm-esas quick-image`)
   # ----------------------------------------------------------------------------
   [quick_image]
   dir = "quick_image"                   # Output directory for quick-look flux images
   bin_size = 50                         # Spatial pixel bin size (50 physical units = 2.5 arcsec/pix)
   with_vignetting = true                # Apply telescope vignetting correction in eimageget
   with_asmooth = false                  # Run eimagecombine asmooth (false = keep unsmoothed sub/exp maps)
   combine_instruments = true            # Merge MOS1 + MOS2 + PN via eimagecombine per target band
   attfile = ""                          # Attitude FITS file ("" = auto-locate atthk.fits or run atthkgen)
   default_subband_edges = [350, 500, 750, 1000, 1500, 2000, 3000, 4500, 7000, 10000]
   evqpb_extra_params = {}               # Extra key=value parameters passed through to `evqpb`
   eimageget_extra_params = {}           # Extra key=value parameters passed through to `eimageget`
   eimagecombine_extra_params = {}       # Extra key=value parameters passed through to `eimagecombine`

   # Optional per-instrument GTI overrides (relative to workdir or absolute).
   # When omitted, GTI files are loaded automatically from soft_proton_flare/manifest.json.
   # [quick_image.gti_files]
   # mos1 = "soft_proton_flare/mos1S001-gti.fits"
   # mos2 = "soft_proton_flare/mos2S002-gti.fits"
   # pn = "soft_proton_flare/pnS003-gti.fits"

   # Target energy bands for quick-look flux maps.
   # If `subbands` is omitted or empty, the band is automatically split along `default_subband_edges`.
   [quick_image.bands.soft]
   emin = 500                            # Soft band lower bound (eV)
   emax = 2000                           # Soft band upper bound (eV)
   subbands = [[500, 1000], [1000, 2000]]

   [quick_image.bands.hard]
   emin = 2000                           # Hard band lower bound (eV)
   emax = 7000                           # Hard band upper bound (eV)
   subbands = [[2000, 4500], [4500, 7000]]

   # Optional additional band example:
   # [quick_image.bands.broad]
   # emin = 500
   # emax = 7000
   # subbands = []                       # Auto-split using default_subband_edges

   # ----------------------------------------------------------------------------
   # Stage 4: Per-Region Spectrum & QPB Extraction (`xmm-esas spectrum`)
   # ----------------------------------------------------------------------------
   [spectrum]
   max_workers = 2                       # Concurrent worker threads across independent regions
   elow = 400                            # Default lower energy bound for mosspectra/pnspectra (eV)
   ehigh = 12500                         # Default upper energy bound for mosspectra/pnspectra (eV)
   pattern_mos = 12                      # Event pattern threshold for MOS1 / MOS2
   pattern_pn = 4                        # Event pattern threshold for EPIC-pn
   withsrcrem = true                     # Apply cheese point-source masks (requires `cheese` stage)
   keepinterfiles = true                 # Keep intermediate spectra and exposure products
   withplotfiles = true                  # Generate QDP diagnostic plots in mosback/pnback
   mos1_ccds = "T T F T T F T"           # Active MOS1 CCDs (CCD3 & CCD6 disabled after micrometeoroid damage)
   mos2_ccds = "T T T T T T T"           # Active MOS2 CCDs
   pn_quads = "T T T T"                  # Active EPIC-pn quadrants
   spectra_extra_params = {}             # Extra key=value parameters for mosspectra/pnspectra
   back_extra_params = {}                # Extra key=value parameters for mosback/pnback

   # Define one [[spectrum.regions]] entry per region file:

   [[spectrum.regions]]
   name = "full_fov"
   file = "regions/full_fov.reg"         # DS9 fk5 .reg file (or pre-converted SAS DETX/DETY .txt)
   mode = "single"                       # 1 shape -> spectrum/full_fov/
   overwrite = false                     # Set true to force re-extraction and upsert manifest.json

   [[spectrum.regions]]
   name = "background"
   file = "regions/combined_background.reg"
   mode = "union"                        # Merges all shapes with || -> spectrum/background/
   overwrite = false

   [[spectrum.regions]]
   name = "east_jet"
   file = "regions/east_jet_bins.reg"
   mode = "split"                        # Splits each shape by DS9 text={label} -> spectrum/east_jet/<label>/
   overwrite = false
   # elow = 500                          # Optional per-region energy override (eV)
   # ehigh = 7000

   # ----------------------------------------------------------------------------
   # Legacy / Multi-Band Imaging Settings (reserved for future ESAS imaging)
   # ----------------------------------------------------------------------------
   [imaging]
   bands = [[400, 1250], [2000, 7000]]   # Energy bands [elow, ehigh] (eV)
   binning = 2                           # Spatial image binning factor

4. Key Section Details & Best Practices
---------------------------------------

``[env]`` & Offline Docker Containers
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

- ``sas_ccf`` and ``sas_odf`` can be relative to ``workdir`` or absolute paths.
- When running inside a headless ``xmmsas`` Docker container that does not have
  ``astropy-regions`` installed in its system Python, point
  ``[env].regions_path`` (or the ``XMM_REGIONS_PATH`` environment variable) to
  a directory containing the ``regions`` package.

``[espfilt]`` Flare Filtering Diagnostics
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

After running ``xmm-esas flare`` (or ``xmm-esas run``), inspect the light-curve
histograms with :doc:`gui_tools` (``xmm-qdp soft_proton_flare/mos1_evt-hist.qdp``).
If a detector has residual flares or overly aggressive clipping, adjust
``rangescale_mos``, ``rangescale_pn``, or ``allowsigma`` and re-run with
``--force``.

``[[spectrum.regions]]`` Extraction Modes
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Each ``[[spectrum.regions]]`` block supports three ``mode`` values:

- ``"single"``: expects a single region shape (or a pre-converted DET ``.txt``
  file) and writes outputs to ``spectrum/<name>/``.
- ``"union"``: combines all shapes in the DS9 ``.reg`` file with logical OR
  (``||``) into one combined region under ``spectrum/<name>/``. Ideal for
  multi-box or multi-circle background regions.
- ``"split"``: expands every shape in the DS9 ``.reg`` file into its own
  sub-region under ``spectrum/<name>/<label>/``, using each shape's DS9
  ``text={label}`` metadata (for example, strip grids exported by ``xmm-img``).

What ``xmm-esas spectrum`` does for each region:

1. Converts DS9 sky shapes (``circle``, ``ellipse``, ``box``, ``polygon``) into
   per-instrument ``DETX/DETY`` expressions via ``evselect`` + ``ecoordconv``.
2. Pre-counts events via ``evselect``; instruments with ``0`` events are marked
   ``skipped = true`` in ``spectrum/manifest.json`` and skipped cleanly.
3. Runs ``mosspectra`` + ``mosback`` and ``pnspectra`` + ``pnback``.
4. Runs ``protonscale mode=1 maskfile=<prefix>-fovimspdet.fits specfile=<prefix>-fovt.pi``
   and records ``proton_area``, ``proton_ave_flux``, and ``proton_scale``
   (``Scaled Ave Flux``) in ``spectrum/manifest.json`` for :doc:`sherpa_joint_fit`.

5. Output Directory Layout
--------------------------

After a complete run, ``workdir`` is organized as follows:

.. code-block:: text

   esas_work/
   ├── esas.toml
   ├── ccf.cif
   ├── <rev>_<obsid>_SCX00000SUM.SAS
   ├── mos1_evt.fits -> _chain_work/...
   ├── mos2_evt.fits -> _chain_work/...
   ├── pn_evt.fits -> _chain_work/...
   ├── pn_oot_evt.fits -> _chain_work/...
   ├── _chain_work/
   ├── soft_proton_flare/
   │   ├── manifest.json
   │   ├── mos1_evt-allevc.fits
   │   ├── mos1_evt-hist.qdp
   │   └── ...
   ├── cheese/
   │   ├── manifest.json
   │   ├── emllist.fits
   │   ├── mos1_evt-cheeset.fits
   │   └── ...
   ├── quick_image/
   │   ├── manifest.json
   │   ├── soft_500_2000_flux.fits
   │   └── hard_2000_7000_flux.fits
   └── spectrum/
       ├── manifest.json
       ├── background/
       ├── east_jet/
