ESAS Configuration & Pipeline (``esas.toml``)
=============================================

All ``xmm-esas`` stages are driven by a single commented ``esas.toml`` file generated by
``xmm-esas init``. Each stage writes a ``manifest.json`` contract so downstream steps
automatically locate cleaned events, masks, spectra, and ``protonscale`` values.

1. Initialize Observation
-------------------------

.. code-block:: bash

   xmm-esas init --odf-dir /path/to/ODF --workdir ./esas_work --ccfpath /ccf/valid
   # Or execute inside a Docker container:
   xmm-esas init --odf-dir /path/to/ODF --workdir ./esas_work --docker xmm-sas-workdir

This runs ``cifbuild``, ``odfingest``, ``emchain``, and ``epchain`` (normal + OOT),
standardizes ``mos1_evt.fits``, ``mos2_evt.fits``, ``pn_evt.fits``, ``pn_oot_evt.fits``,
and writes ``esas.toml``.

2. ``esas.toml`` Sections
-------------------------

``[env]`` & ``[paths]``
~~~~~~~~~~~~~~~~~~~~~~~

.. code-block:: toml

   [env]
   sas_ccf = "ccf.cif"
   sas_ccfpath = "/ccf/valid"
   sas_odf = "SUM.SAS"
   regions_path = ""   # Optional fallback path for 'regions' inside offline Docker (e.g. "/tmp/xmm-coordinates-deps")

   [paths]
   workdir = "."
   flare_dir = "soft_proton_flare"
   cheese_dir = "cheese"
   spectrum_dir = "spectrum"
   image_dir = "images"

- If ``astropy-regions`` is not installed in a headless Docker container, set ``[env].regions_path``
  (or ``XMM_REGIONS_PATH``) to the directory containing ``regions``.

``[instruments]``
~~~~~~~~~~~~~~~~~

Leave any instrument as ``""`` to disable it for all downstream stages:

.. code-block:: toml

   [instruments]
   mos1 = "mos1_evt.fits"
   mos2 = "mos2_evt.fits"
   pn = "pn_evt.fits"
   pn_oot = "pn_oot_evt.fits"

``[espfilt]`` & ``[source_detect]``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Run soft-proton flare filtering and point-source swiss-cheese masking:

.. code-block:: bash

   xmm-esas flare --config esas.toml
   xmm-esas cheese --config esas.toml

Key options in ``esas.toml``:

- ``[espfilt]``: ``elow`` / ``ehigh`` (2500–8500 eV), ``rangescale_mos`` (6.0), ``rangescale_pn`` (15.0),
  ``apply_flag_filter = true``, ``mos_flag_expr``, ``pn_flag_expr``.
- ``[source_detect]``: ``elowlist`` / ``ehighlist``, ``scale`` (0.4), ``mlmin`` (15.0), ``dist`` (50.0),
  ``extra_regions = []`` (extra DS9 ``.reg`` files merged into masks).

``[spectrum]`` & ``[[spectrum.regions]]``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Configure ``mosspectra``/``pnspectra``, ``mosback``/``pnback``, and automatic ``protonscale``:

.. code-block:: toml

   [spectrum]
   max_workers = 2
   elow = 500
   ehigh = 2000
   pattern_mos = 12
   pattern_pn = 4
   withsrcrem = true
   keepinterfiles = true
   withplotfiles = true
   mos1_ccds = "T T F T T F T"
   mos2_ccds = "T T T T T T T"
   pn_quads = "T T T T"

   [[spectrum.regions]]
   name = "full_fov"
   file = "regions/full_fov.reg"
   mode = "single"      # Single region -> spectrum/full_fov/
   overwrite = false

   [[spectrum.regions]]
   name = "background"
   file = "regions/combined_background.reg"
   mode = "union"       # Merges all shapes in file with || -> spectrum/background/
   overwrite = false

   [[spectrum.regions]]
   name = "east_jet"
   file = "regions/east_jet_bins.reg"
   mode = "split"       # Splits each shape by DS9 text={label} -> spectrum/east_jet/<label>/
   overwrite = false

Running Spectrum Extraction
~~~~~~~~~~~~~~~~~~~~~~~~~~~

.. code-block:: bash

   # Run all pending/new regions (existing entries in spectrum/manifest.json are skipped unless overwrite=true)
   xmm-esas spectrum --config esas.toml

   # Re-run only one group or ad-hoc region and upsert into spectrum/manifest.json
   xmm-esas spectrum --only background --force
   xmm-esas spectrum --reg regions/new_knot.reg --name knot1 --mode single

What ``xmm-esas spectrum`` does per region:

1. Converts DS9 sky regions (``circle``, ``ellipse``, ``box``, ``polygon``) to per-instrument
   ``DETX/DETY`` expressions via ``evselect`` + ``ecoordconv``.
2. Pre-counts events via ``evselect``; instruments with ``0`` events are marked ``skipped=true``
   and safely skipped.
3. Runs ``mosspectra`` + ``mosback`` and ``pnspectra`` + ``pnback``.
4. Runs ``protonscale mode=1 maskfile=<prefix>-fovimspdet.fits specfile=<prefix>-fovt.pi``
   and saves ``proton_area``, ``proton_ave_flux``, and ``proton_scale`` (``Scaled Ave Flux``)
   into ``spectrum/manifest.json``.

``[quick_image]``
~~~~~~~~~~~~~~~~~

Generate QPB-subtracted, vignetting-corrected flux images:

.. code-block:: bash

   xmm-esas quick-image --config esas.toml
